## 🔴 FLUXO DO DIA A DIA (use sempre nessa ordem)

Sempre que terminar uma mudança que funcionou, siga esses 3 passos:

```powershell
# 1) Testar se compila sem erro
dotnet build

# 2) Se compilou certo, salvar no Git (seu "ponto de restauração" de verdade)
git add .
git commit -m "descreva aqui o que voce mudou"

# 3) Gerar o executável atualizado (opcional, só quando quiser testar o .exe final)
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

⚠️ **Regra de ouro:** só faça `git commit` depois que `dotnet build` funcionar sem erro.
Nunca commite código quebrado — assim você sempre tem um ponto seguro para voltar.

## 🟢 GIT — controle de versão (evita o problema que você teve)

### Configuração inicial (fazer só 1 vez, se ainda não tiver repositório)
```powershell
git init
git add .
git commit -m "Primeiro commit - app funcionando"
```

### Ver o que foi mudado antes de commitar
```powershell
git status
git diff
```

### Salvar mudanças (fazer sempre que uma alteração funcionar)
```powershell
git add .
git commit -m "descreva o que voce mudou, ex: trocar icone dark/light"
```

### Ver histórico de commits
```powershell
git log --oneline
```

### 🆘 Voltar para um commit anterior (se algo quebrar de novo)
```powershell
# Ver a lista de commits e copiar o código (hash) do que quer voltar
git log --oneline

# Voltar TUDO para aquele ponto (descarta mudanças não commitadas)
git reset --hard <hash_do_commit>
```

### Criar um "checkpoint" rápido sem descrever nada (uso emergencial)
```powershell
git add .
git commit -m "checkpoint antes de mexer no icone"
```

## 🔵 BUILD, RUN E TESTES

### Restaurar pacotes (dependências do projeto)
```powershell
dotnet restore
```
O que faz: baixa e instala as dependências do projeto.

### Compilar a solução (só verifica se está tudo certo)
```powershell
dotnet build SystemWM.sln
```
O que faz: verifica se o código está correto e gera o binário para testar.

### Limpar build antigo (quando algo estranho não muda mesmo depois de editar)
```powershell
dotnet clean SystemWM.sln
```
O que faz: remove os arquivos temporários gerados pela compilação. Use isso se corrigir um bug e o erro continuar aparecendo igual.

### Rodar o programa em modo de desenvolvimento
```powershell
dotnet run --project SystemWM\SystemWM.csproj
```
O que faz: inicia o aplicativo localmente para testar.

⚠️ **Este projeto precisa de permissão de administrador.** Se aparecer erro 740, abra o PowerShell **como Administrador** e rode o comando de novo.

### Rodar o .exe gerado diretamente
```powershell
.\bin\Debug\net8.0-windows\win-x64\WYSHUB.exe
```

---

## 🟣 PUBLICAR EXECUTÁVEL FINAL (para usar em outra máquina)

```powershell
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```
O que faz: gera um arquivo `.exe` único, pronto para usar em outra máquina Windows (não precisa ter o .NET instalado).

- O ícone do programa e o botão do topo da janela já estão conectados ao site:
